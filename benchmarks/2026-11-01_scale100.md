# Hybrid search benchmark: pgvector vs Qdrant

Corpus: 50 PDFs, 215 pages, 1,130 chunks (500 chars / 100 overlap) x **scale 100** = **113,000 chunks** indexed (replicas: same-category blends of two chunks, noise σ=0.01). Embeddings: `sentence-transformers/all-MiniLM-L6-v2` (384-d). 100 queries, top-10, 40 candidates per branch, 10 warm-up queries per engine per run.

Latency: median of **5 runs** (min–max across runs). Load/index: median of **1 build(s)**.

| Metric | pgvector (RRF: HNSW cosine + GIN ts_rank_cd, WHERE filter) | Qdrant (RRF k=60: HNSW cosine + BM25 sparse, payload filter) |
|---|---:|---:|
| Shared preprocessing: parse + chunk + embed, base corpus (s) | 5.01 | 5.01 |
| DB load / upsert (s) | 7.27 | 15.62 |
| **Total ingestion time (s)** | **12.28** | **20.63** |
| **Index creation overhead (s)** | **12.42** | **11.02** |
| **Query latency P50 (ms)** | **36.05** (33.60–37.68) | **3.33** (2.74–9.21) |
| **Query latency P95 (ms)** | **68.02** (61.84–69.12) | **4.04** (3.94–26.69) |
| Query latency P99 (ms) | 84.17 (80.77–87.35) | 6.23 (4.32–29.00) |
| Query latency mean (ms) | 38.20 (36.81–41.77) | 3.36 (2.87–10.04) |
| Pooled P50 / P95 / P99 over all 500 queries (ms) | 36.27 / 68.15 / 87.14 | 3.32 / 12.61 / 26.69 |
| Run-to-run CV of P50 | 4.9% | 62.6% |
| Avg results returned | 10.0 | 10.0 |
| Dense branch alone: rows returned of 40 (mean / min) | 40.0 / 40 | 40.0 / 40 |
| Dense branch alone: recall@10 vs exact (ef_search=64) | 95.3% | 97.2% |

- Load breakdown (s, median): pgvector {'copy': 7.27}; Qdrant {'bm25_encode': 2.363, 'upsert': 13.262}
- Index breakdown (s, median): pgvector {'hnsw': 10.991, 'gin_tsv': 0.728, 'btree_category': 0.053, 'analyze': 0.644}; Qdrant {'payload_index_category': 2.038, 'hnsw': 8.98}
- Access path, 1-category filter: pgvector plan uses ['Bitmap Index Scan: policy_chunks_category', 'Bitmap Index Scan: policy_chunks_tsv_gin', 'Index Scan: policy_chunks_hnsw', 'Index Scan: policy_chunks_pkey'] (HNSW used); Qdrant expected filtered HNSW (11,000 matching vectors = 16,500 KB vs full_scan_threshold 10,000 KB)
- Access path, 2-category filter: pgvector plan uses ['Bitmap Index Scan: policy_chunks_category', 'Bitmap Index Scan: policy_chunks_tsv_gin', 'Index Scan: policy_chunks_hnsw', 'Index Scan: policy_chunks_pkey'] (HNSW used); Qdrant expected filtered HNSW (22,500 matching vectors = 33,750 KB vs full_scan_threshold 10,000 KB)
- Query embedding (sentence-transformers/all-MiniLM-L6-v2, shared, not in latency above): 3.20 ms/query. Keyword query parsing is inside the timed call on both sides (to_tsquery / BM25 query encoding).
- Top-10 overlap between engines (run 1): 58%. Both are hybrid now; the remaining gap is mostly the keyword scorer (ts_rank_cd vs BM25) and ANN approximation.
- Qdrant transport: gRPC, server 1.20.0; pgvector 0.8.7 (parallel maintenance workers: 2); host macOS-26.6.2-arm64-arm-64bit-Mach-O
